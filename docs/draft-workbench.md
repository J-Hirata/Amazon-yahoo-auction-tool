# ヤフオク出品下書きの作業場

## 現在地と目的

2026-11-10、初期データと旧ツールを再照合して作業の区分を修正。カードの見た目は維持し、作成待ち、入力済み、保存確認済み、出品済み、履歴、アーカイブを分ける。読み取りや配備によって業務データを移行・削除・初期化しない。

## 再照合で分かった問題

- 元のPC版57件、初期クラウド移行バックアップ58件、現クラウド59件をREAD ONLYで比較した。PC版57件の主要項目は一致。初期58件は全件存在し、元の全保存項目に差分0。クラウド側の追加商品は上書きせず保持する。写真の追加参照とworkPriorityなど追加項目を元の値の破壊と混同しない。
- 前回のカード化では、作成待ちにdraft_savedの31件を混ぜ、以前の「貼り付け完了」の履歴欄と候補へ戻す操作をなくしてしまった。初期データの保全だけでは作業の意味を引き継げていなかった。
- 旧public/yahoo-fill.jsは、フォーム入力や「次へ」でもdraft_savedを送っていた。旧Chrome拡張もPATCHを一律draft_savedへ置き換え、本文を渡していなかった。旧31件を実際のYahoo保存済みと断定できない。現在の画面表示は「旧・貼り付け完了（保存未照合）」とし、元のstatusや日時は読み取り時に変更しない。
- 現データの内訳は作成待ち28件（準備済み26、情報待ち2）、旧入力記録31件。保存確認済み・出品済みの記録は0件。既存日時から読める履歴は35件で、現在の状態が作成待ちへ戻っている商品にも古い入力日時が残っている。

## 状態と操作

| 表示 | 保存状態・根拠 | 次の操作 |
|---|---|---|
| 下書き作成待ち | ready_for_draft / waiting_for_product_data等 | 準備状況を絞り込み、出したい順に並べ替え、文面を作る |
| 入力済み・保存確認 | input_done または保存確認日時のない旧draft_saved | Yahoo側の保存を確認し、保存確認・出品完了を別に記録する |
| 下書き保存済み | draft_savedとdraftSaveConfirmedAt | 保存を確認した記録。出品を確認したら別に出品済みを記録 |
| 出品済み | listed | 本人が出品完了を記録した商品 |
| 売却済み | sold | 本人が売却完了を記録した商品 |
| 履歴 | 既存日時とworkHistory | 日時順に旧入力記録と状態変更を確認し、商品別の履歴・整理を開く |
| アーカイブ | archived / 旧deleted | 作業から外して保管。元の状態へ戻せる |

- 商品カードは各状態で1商品1枚。履歴は商品一覧と別の時系列表示で、直近20件制限をなくす。作成待ちに入力済み・保存済みを混ぜない。準備完了・情報補完は作成待ち内の絞り込みとする。
- 「履歴・整理」で元の登録日時・入力日時・保存確認・出品記録・アーカイブと復元を確認できる。「下書き作成待ちへ戻す」でも以前の日時・説明・写真・価格は消さない。
- 選択チェック、表示中の全選択、選択解除、選択分のアーカイブ/復元を備える。確定前に全対象の商品名・ASIN・状態を表示し、取消できる。永久削除しない。復元先はサーバーが記録するarchivedFromStatus。古いアーカイブに元の状態がない場合だけ情報補完へ戻す。
- 一括処理は1〜200件を全件検証し、1件でも不正なら保存しない。クラウドの本人認証、同一Origin、JSON、If-Match、閲覧専用ガードを適用。競合時は確認画面を閉じて選択し直し、編集内容は残す。
- 既存の履歴は残っている日時だけを表示する。欠けている操作や出品完了を推測して作らない。workHistoryは本人の操作記録であり、Yahooへの保存・出品を自動検証した証拠ではない。

## 入力・保存・出品の区別

- PC版でフォーム入力、フォームを空にして次の商品へ進む操作、Yahoo保存ボタンを押しただけの段階ではinput_doneを記録する。保存ボタンのクリックだけで完了とはしない。
- 「Yahoo保存を確認・記録」等の明示操作だけがsaveConfirmed:trueを送信し、draftSaveConfirmedAtを付ける。古いクライアントのstatus:draft_savedだけの通知は保存確認にならない。旧入力通知で保存確認済み・出品済み・売却済み・アーカイブを戻さない。
- 拡張1.0.3はinput_doneと明示確認付きdraft_savedを区別して渡す。別の状態・価格・商品名の変更をこの橋渡し経路では受け付けない。公開ファイルと拡張同梱yahoo-fill.jsを一致させる。
- PC版PATCHも同じ状態変更処理を使う。状態だけの変更でstartPrice/stalePriceが欠落していた処理も修正した。
- 既に読み込まれたPCサーバー・拡張は自動更新されない。PC入力補助を試す前に正本側の拡張を再読み込みし、利用するサーバーの版を確認する。古いOneDrive側のフォルダ・実行中41731プロセスは変更・停止していない。

## 写真・商品名・並び順

- 登録写真を優先し、不足分は同じASINの取得済みAmazonカタログ写真を参照表示する。別ASINや現物写真を推定流用しない。参照表示でDBへ保存しない。
- 写真付きタイル、小・標準・大、リスト、検索、既存の表示設定を維持する。タグは高さを固定せず、本文や価格に重ならないよう折り返す。
- 作業順はworkPriorityで保存。ドラッグ・矢印・キーボード移動に対応。絞り込み中は表示中の商品だけを入れ替え、隠れた商品の順序を保つ。「次の下書き文面」とCSVは作成待ちの準備済みを使う。CSVは既存の先頭10件仕様を明記する。
- 長い説明・写真URL・価格・状態は編集ダイアログで変更欄だけ保存。旧入力記録を編集しただけで保存確認済みにはしない。
- ASIN補完は既存のAmazon Catalog Items APIを使い、商品名・MAIN画像のASIN一致を検証。1回5件まで、価格・説明・状態を変えず、不足欄だけ補完する。

## 検証と残件

- 初期58件の全項目比較、現クラウド59件のREAD ONLYスナップショット、元PC版57件の比較結果はoutput/draft-original-all-fields-20261110.json、draft-reconciliation-20261110.jsonへ保存（Git対象外）。
- 単体/API検証：旧入力と保存確認の区別、旧拡張からの誤確認防止、作成待ちの分離、旧日時保持、再保存履歴、各状態のアーカイブと復元、一括処理の原子性、価格保全、認証・Origin・閲覧専用・競合。拡張の内容→バックグラウンド→API本文の境界も検証する。
- 隔離画面で旧入力記録の編集、明示保存確認、アーカイブ、元の保存済み状態へ復元、出品記録への移動を確認。実59件の読み取り見本で作成待ち28件・旧入力31件と旧日時の表示を確認。実商品のアーカイブや出品は代行していない。
- クラウドとPC版の自動同期、クラウドからの拡張入力、実Yahoo保存/出品との自動照合は未接続。旧31件の実保存・実出品の照合は残る。SKU・状態ごとの同一ASINの下書き複製、新規Amazon取得の実例確認も引き続き残件。
- 外部出品、価格、実在庫、メール、Cronの変更・実行は今回行わない。
