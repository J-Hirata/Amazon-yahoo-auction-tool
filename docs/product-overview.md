# 全商品一覧と商品監視

入口： https://amazon-yahoo-inventory.vercel.app/?view=overview 。配備・有効化・実送信の最新結果はstatus.mdを正本とする。

## 使い方

- 紐付け・場所別在庫・販売見直し・下書き・監視だけの商品を写真付きで横断表示する。明示された関連付けだけをまとめる。同じASINでも状態/SKU/管理単位が異なる商品を混ぜない。
- Amazon対象・ヤフオク紐付け・併売紐付け・コンテナ・自宅自社・監視・過多・大型・重量物・見直し・下書きを色と文字で表示。検索、区分絞り込み、確認日/FBA数/7日販売順、タイル/リストを利用できる。
- 「監視・補充設定」でタグ、FBA閾値、7日販売の最低数、残り日数、販売可能確認日と見直し日数、メモを保存する。「監視商品を追加」はASIN/名前だけでも追加でき、現物数量は作らない。
- 数量と関係の編集は元の画面が正本。FBAとコンテナ/自宅自社を合算しない。写真欠損は代替画像、数量未確認は未確認としゼロと区別する。

## 通知

既存の日次ジョブ（午前9時台）に登録ASINのFBA、登録ヤフオクIDの公開ページ、計画/監視の期限を追加する。宛先は既存固定Gmailのみ。FBA0/補充、ヤフオク終了、期限を種類別に停止できる。初回から問題があれば初回通知し、同じ状態が続くだけでは毎日送らない。

1. FBA販売可能0：自社アカウント・SKU・状態・取得範囲を確認できる場合だけ通知する。カタログの購入可否や手元在庫ゼロを意味しない。予約/処理中や取得不能は区別する。複数SKUを一意に解決できなければ数量は未確認。
2. 補充：手元の使用可能数が正で、「FBA数が閾値以下」または「残り日数が指定以下」、かつ最低7日販売数を満たすと候補通知する。残り日数はFBA販売可能数÷直近7日FBA販売の日平均。自己発送の売上はFBA回転へ混ぜない。7日分の観察・取得完了がなければ回転率を推定せず、販売数/日数の条件を保留する。0指定の販売数/日数条件は使わない。
3. ヤフオク終了：公開構造化データの出品ID・売主・管理ASINを検証する。closedと明示的な入札0なら落札なし終了。入札があっても落札成立は断定しない。404、ログイン、構造変更、識別不一致は未確認で、終了/売れ残りにしない。未確認の商品IDを一覧で確認できる。
4. 期限：既存計画の確認日、または監視設定の販売可能確認日+日数で通知。未確認日付や予定日からは開始しない。同じ計画/日付で1回、延期した日付は別の確認とする。広告や価格は自動変更しない。

初期設定は本人依頼に基づき、TOYOオレンジを監視、FBA10個以下・7日FBA販売1個以上で補充検討。スプレーは監視/在庫過多、既存11/12確認日を利用する。既存数量・計画ID/日付を作り直さない。

## 保存・失敗時・上限

商品設定と観測は同じ専用DBのproduct-watch文書へ分離。004-product-watch.sqlは空文書のINSERTのみ。既存4文書の版/ハッシュ不変を確認。アプリのSELECT/UPDATE権限は維持し、管理接続で一度だけ初期化する。

操作ID/内容と保存世代で並行登録を保護。監視文書に安定IDで通知保存→メール文書でID重複検査してまとめ通知→受付記録の順。途中失敗や保存応答消失でも同じ通知を作り直さない。送信前に解消した保留通知は取り下げる。SMTP結果不明は無条件再送しない。

1回はFBA100 ASIN、ヤフオク20 IDまで。超過は部分完了/未確認とし、ヤフオクは古い確認から順に再開する。大量登録で全件を毎日処理するには分割実行の拡張が必要。日次なので閾値に達した瞬間の通知ではない。実行上限300秒、時間不足の送信待ちは次回へ残す。[Vercel公式の実行上限](https://vercel.com/docs/functions/limitations)

## 検証・残件

隔離データで明示参照/未関連/状態違い、7日未満、FBA/自己発送、未知/失敗/古い情報、通知再発/重複/途中保存、404と終了、期限、権限/世代を試験。画面は絞り込み・保存再読込・監視専用登録・390px幅を検証する。本番へ架空商品や数量ゼロを登録しない。

広告API取得、広告費/利益を含む補充最適化、CSV取込、物理寸法/重量、写真アップロード、ヤフオク後継IDの追跡、現物自動減算は後段。大型/重量物/過多は初版では本人のタグ指定である。
