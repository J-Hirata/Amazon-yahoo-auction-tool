## 今回追加した検査

`scripts/auth-build-boundary.mjs` と `tests/auth-build-boundary.test.mjs` を追加した。Neonへ認証処理を任せ、APIはリモートJWKSでJWTを検証する現行設計を前提とする。ログイン方式や権限・認証設定は変えない。

- ブラウザの実ビルドにMagic Link/OAuth Proxyのサーバーハンドラー、サーバーAPI/DB、監査対象のアダプター、メール描画依存が出力されていないか検査する。
- メタファイルの入力一覧だけでなく出力へ実際に残ったバイトを使い、tree-shaking済みの入力を配備コードと誤認しない。クライアント用Magic Linkとサーバーハンドラーを分け、Lucideのcloud-drizzleアイコンも誤検出しない。
- API関数内には認証SDK/Better Auth/関連アダプター/メール描画依存を入れない。JWT検証のjoseと自社認証モジュールは維持する。
- Windows・入れ子のnode_modulesにも対応する。検査したログインバンドルのSHA256を実際の配備ファイルと照合し、別のコードを検査して合格することを防ぐ。
- `scripts/verify-vercel-package.mjs` の既存7検査にこの境界検査を追加し、8検査とした。現配備パッケージ688ファイルで合格。単体試験は既存257+追加6=263件合格。

これは既知の構成逸脱を防ぐ検査であり、すべての脆弱性がない証明やNeon管理サーバーの監査ではない。認証の構成変更が必要になった場合、この検査だけを無断で解除しない。
