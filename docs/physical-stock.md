# コンテナ・自社在庫の操作と保存仕様

更新: 2026-10-26。進捗の正本は [status.md](status.md)。本書はフェーズ2Aの手入力台帳の仕様・操作手順。

## 入口と最初の1商品

https://amazon-yahoo-inventory.vercel.app/?view=stock を開き、いつもの本人アカウントでログインする。上部の「コンテナ・自社在庫」からも移動できる（旧名：手元在庫）。PCの起動やPowerShellは不要。

## 共通のリスト・タイル表示

コンテナ・自社在庫、商品紐付け、出品下書きの3画面に「リスト」「タイル」と並び順を追加する。初回は従来のリスト。選択はこのブラウザの画面別localStorageへ保存し、DBや在庫・出品を変更しない。別端末への表示設定の同期はしない。表示順の変更は出品キューの業務順や登録順を書き換えない。

- タイルは十分な表示幅のPCで5列のほぼ正方形。狭い画面は4/3/2列へ調整し、スマホは2列で読みやすい高さを確保する。画像/商品名2行/要点の状態/主要な数値を表示し、商品名の全文は詳細またはタイトル属性で確認できる。下書きもタイル時は候補/待機を全幅の別グループにする。
- コンテナと自宅・会社の数量は別表示。FBA数量と合算しない。全場所が確認済みの場合だけ確認済み合計で数量順に並べ、未確認を0として並べない。
- 紐付けでは鮮度・状態が確認できるFBA取得数と、追跡済み注文確定数を別表示する。取得分はMCF可否の保証ではない。未知/古い/不一致は未確認で、注文数も未追跡を0にしない。
- 下書きは写真/商品名/状態と価格案を表示する。価格案を現在の販売価格や在庫数として見せない。現在の下書き候補/待機の区分は維持する。
- 「詳細」でその商品の元の操作欄を展開する。操作DOMをコピーせず、数量編集/紐付け/メモ/下書き等のイベントと権限を保持する。モード切替・並び替えでは入力中のメモを破棄しない。
- 元の並び順、自由な並び順、登録日（新しい/古い）、確認済み数量（多い/少ない、下書きは価格案）、商品名の昇順/降順を用意する。不明はどちらの方向でも最後。同じ値では元順を保つ。数量・価格・商品の業務配列を保存し直さない。
- タイル下部のグリップをドラッグ、前/後の矢印、またはグリップにフォーカスして矢印キー/Home/Endで自由配置する。自動で「自由な並び順」へ切り替え、同じブラウザへ保存。リストにも同じ表示順を適用し、再読込しても保持する。並び替え時に絞り込みで隠れたIDを破棄しない。新規IDは末尾。スマホでドラッグが難しい場合も矢印で操作できる。ドラッグ機構は [SortableJS](https://github.com/SortableJS/Sortable) 1.15.7をクラウドの静的アセットへ束ねる。旧ローカル版では当該アセットがない場合、矢印操作を利用する。
- 下書きの候補/待機/履歴の間をドラッグで移動させない。業務状態の変更は従来の明示操作のみ。詳細展開中のタイルもドラッグ対象外とし、未保存フォームを維持する。
- 登録日はstock/draftのcreatedAt、紐付けは今後の初回登録createdAtを使う。紐付けの再確認日は登録日ではない。既存のcreatedAtがない紐付けは「不明」のまま、reviewedAt/更新日から推定・補完しない。登録日不明の既存商品は元順か自由配置で整理できる。
- 写真がない/読み込めない場合は写真未登録のプレースホルダーにし、他商品の写真を推測で入れない。切替アイコン等は既存Lucide由来のSVGで、ライセンスを各資産に保持する。

## ヤフオクへの併売と紐付け（操作）

上部はA/Yロゴ付きの「Amazon・ヤフオク併売」に「商品紐付けツール」「出品下書きツール」を隣接させ、「在庫管理」の「コンテナ・自社在庫」と分ける。下書きQという略称を主メニューから外し、画面見出し/ブラウザタイトルも用途の分かる名前に揃える。

コンテナ・自社在庫の商品行の「ヤフオクと紐付け」から次の流れで行う。

1. 既存の「商品紐付けツール」へ登録済みの出品は、同ASINの候補から選ぶ。既に関連付けた出品は固定表示で、ここでは解除しない。
2. 「選んだ出品との紐付けを確認」で対象の出品IDを見て、「この内容で保存」で確定する。確認/取消だけでは保存しない。保管場所の数量・用途・SKUは変更しない。
3. 未登録の出品URLがある場合は「出品URLを登録する」へ進む。対象商品名とASINを引き継ぎ、既存の「この2つを紐付ける」でページ同士を登録する。その後「この出品を在庫に関連付ける」で在庫側へ戻り、確認して保存する。ページ登録と在庫側保存は別操作なので、途中で止まっても在庫に保存したとは扱わない。
4. まだ出品していなければ「未出品：下書きを作る」でASINを出品下書きツールへ引き継ぐ。入力だけで下書き追加/ヤフオク出品はしない。出品後にURLを登録し、上記の関連付けを行う。

対象在庫のIDは本人認証後の在庫APIと照合する。URLには秘密値や商品名を入れず、フラグメントのUUIDだけで対象を参照する。存在しないIDは警告し、API操作は引き続き本人認証/版番号/確認画面を必須とする。状態/SKUが明確に違う候補の追加は画面・サーバー双方で拒否する。状態不明の候補は不明と表示し、本人の確認を必要とする。ASINなしは商品情報で登録してから進む。

これは出品と現物在庫の参照関係であり、コンテナ/自宅在庫をFBAへ加算する機能ではない。現在の通知プレビューはFBA監視が中心で、自己発送在庫に応じた在庫切れ判定/発送元の割当/売上からの数量減算/自動停止は未実装。FBA0とコンテナ0を混同せず、自動メールは有効化しない。

## 用途・写真・販売先の見分け（詳細）

用途は新規登録画面の上部と、各商品の名前のすぐ下に表示する。保存済みの商品は一覧の用途選択から変更前後を確認して保存できる。用途での絞り込みも可能。

- FBA補充用：Amazon FBAへ追加納品する予定の在庫。Amazon側の納品資格や出品状態を確認済みという意味ではない。
- 自社発送用（FBA不可）：FBAへ納品できず、自社から発送する在庫。
- 用途未設定：まだ決めていない。保管場所とは別項目で、コンテナにあっても自社発送用にできる。

写真は、保存済み画像→明示的なヤフオク紐付け画像→同ASINのAmazon保存画像/下書き画像→同ASINのヤフオク参考画像の順に表示する。参考画像の利用だけでは紐付け済みにしない。Amazon画像は現物写真ではないことをalt/titleに明記する。登録画面の詳細でAmazon/ヤフオクのHTTPS画像URLも入力できる。ASIN修正時は古い自動取得画像を消し、前ASINの画像を表示し続けない。

「商品写真を取得」は、画像未保存でASINがある商品だけを最大8 ASINずつAmazon Catalog Items APIから読む。日本市場のMAIN画像だけを保存する。失敗時に現在の画像や数量を消さず、ASINなしの商品を名前で推測しない。APIの仕様根拠は [Amazon公式モデル](https://github.com/amzn/selling-partner-api-models/blob/main/models/catalog-items-api-model/catalogItems_2022-04-01.json)。写真更新は在庫数量やAmazon出品への書込みではない。

「販売先の状況」列は「Amazonの自社出品」と「ヤフオクとの関連付け」を分離する。ヤフオクの登録がないだけでAmazonも未出品に見える「未紐付け」という一括表示はしない。ヤフオクは明示的に関連付けた出品ID/取得できた状態/FBA参考情報と、「同ASINの候補」を分ける。候補の確認ボタンは商品編集の選択を開くだけで、勝手に確定しない。

「Amazon自社出品を確認」は、接続済みの自社出品者IDで登録ASINだけをListings Items APIから読み、販売中/自社出品あり・購入可否要確認/状態・SKU違い/確認できず/取得失敗/古い情報を区別する。カートの販売元や他社出品は判定に使用しない。根拠は [Amazon公式 searchListingsItems](https://developer-docs.amazon/sp-api/reference/searchlistingsitems)。BUYABLEのある自社SKUだけを販売中とし、DISCOVERABLEのみでは販売可能と断定しない。

新品中古の区分と登録済みSKUを照合するが、ASINが同じだけで現物やSKUを自動統合しない。自社出品の各SKUは状態/自己発送・FBA/購入可否を別々に表示し、手元の数量を足し合わせない。「Amazon自己発送の設定数」は出品設定であり、コンテナや自宅の実数ではない。FBAの発送可能数量やMCF可否をこの応答から推定しない。

確認結果は `physical-stock.amazonListings` の観測メタデータに保存する。商品、新品中古、場所別残高、移動、既存履歴/受付、ヤフオク関連付けは変更しない。結果が90分を超えたら再確認表示にし、失敗時も過去結果を現在値として使わない。自社出品0件の応答も在庫ゼロとは扱わず、登録ASIN/SKU/接続を確認する。初期上限は20 ASINで、超過時は黙って一部を省略せず分割対応が必要と通知する。Amazonへの書込み、メール送信、定期確認は行わない。

紐付け画面にも、明示的関連または同ASIN候補のコンテナ/自宅・会社数量へのリンクを表示する。状態・SKU・セット違いの複数候補は合算せず候補件数を表示する。保存済みの同じ商品IDを参照し、同じ現物を別販路分として増やさない。

画面切替時はログイン欄を最初から隠し、セッション確認中は中立の準備表示を出す。認証済みデータは引き続きJWT/本人APIで確認する。匿名/実際の401/権限エラーはログイン画面へ戻し、前回ログインの印だけで認証を省略しない。フルページ移動自体をSPAに作り直した変更ではない。

1. 「商品を登録」を押す。既存の紐付けがあれば選ぶ。ない商品やASIN未作成の商品も登録できる。
2. 商品名、新品/中古を入力する。単位選択はなく、新規登録は「個」に固定。同じ型番でも状態やセットが違えば別商品にする。状態・付属品・セット内容は任意で、空欄でも進められる。
3. 「場所ごとの数量」にコンテナと自宅・会社の使用可能数をそれぞれ入力する。同じ現物を2か所に足さない。未確認なら空欄にする。0は在庫なし、空欄は未確認。片方だけでも両方同時でも登録できる。
4. 必要ならメモを入力する。「Amazon・ヤフオク／カタログ設定」内の追加項目は任意。既存の紐付け選択もこの詳細内にある。
5. 「変更内容を確認」で変更前後を見て、「この内容で保存」を押す。確認だけ、または閉じただけでは保存しない。
6. 一覧の管理ID・場所・数量を見て、「更新」やページ再読込でも残ることを確認する。

最初は本人が実際の1商品でこの流れを確認し、その後に残りを登録する。試験用の架空商品を本番へ自動登録していない。390px幅の検証は済んでいるが、PC停止中の実機スマホ回線の確認は本人と行う。

## 数量の操作

普段は商品行の「数量を編集」、または各場所の数量/未確認を押す。コンテナと自宅・会社の実数を入力し、変更前後を見て保存する。Dellのコンテナ3個が登録済みで、自宅に1個ある場合はコンテナ3のまま自宅1とする。これは操作説明であり、今回本人の代わりに1を登録してはいない。数量を空欄にして確認済みデータを消すことはできず、在庫なしには0を明示する。

「数量を編集」は使用可能数だけを対象にし、既存の取り置き/使用不可数を保持する。変更した場所だけを1操作として版番号付きで原子的に保存する。変更理由は任意入力で、空欄なら「場所ごとの実数を確認」を履歴へ残す。

増えた分・減った分を記録する場合は「入出庫・移動」を開く。まず「入庫」「販売・持ち出し」「場所を移す」の3モードを表示する。取り置き、使用不可、区分別棚卸し、到着/戻しは「その他の操作」内。毎回変更前後を確認して保存する。

| 操作 | 意味 |
| --- | --- |
| 追加 | 今の使用可能数に足す。6台に3台追加なら9台 |
| 減少 | 販売・持出しなどで使用可能数から減らす。Amazon/Crossmaの処理とは連動しない |
| 棚卸し | 使用可能・取り置き・使用不可それぞれの実数へ合わせる。実数3台なら3台へ修正 |
| 取り置き/解除 | 使用可能と取り置きの間を振り替える。現物総数は変わらない |
| 使用不可/復帰 | 使用可能と使用不可の間を振り替える。現物総数は変わらない |
| 移動・納品の出発 | 出発元の使用可能数を減らして移動中へ移す |
| 到着/出発元へ戻す | 未到着の範囲内で振り分ける。一部到着も可能 |

場所別の現物数は「使用可能+取り置き+使用不可」。使用可能から取り置きをもう一度引かない。未確認の場所は先に棚卸しする。使用不可品の廃棄や取り置き品の販売は、必要な区分へ戻してから減少させる初期構成で、外部への廃棄依頼等はしない。

移動中は出発元・到着先の両方に重複計上しない。到着先が未確認なら実数を棚卸ししてから到着を記録する。到着済み数量と移動中の数量は別である。

FBAへの出発には納品番号などの参照を必須にし、FBA到着には受領画面等の確認根拠を残す。この手入力はFBA観測値を増やさない。FBA数量はAmazonから確認した別の参考情報として表示し、手元在庫との総合計や、ヤフオクへ発送可能な数量として保証しない。古い情報・取得失敗・SKU/状態不明は数量不明。

## 商品情報・カタログ待ち

- 「情報・メモ」で商品名、メモ、ASIN/SKU、既存紐付け、FBA納品可否、カタログ作業状態、再確認日を更新できる。
- 管理IDは固定。後からASINが付いても商品IDや数量は変わらない。
- 単位・新品中古・状態/セット内容の変更は別商品登録を求める。数量の自動変換や同じASINの合算はしない。単純な誤字訂正も初期版ではロックされるため、本人確認後の改善候補。
- 新規登録の単位は「個」で固定するが、旧データの台/箱等を勝手に個へ変換しない。既存商品編集では元の単位を非表示項目として保持する。過去のコンテナ参考リストの台/箱も過去の記録なのでそのまま残す。
- 同じASINまたは商品名の既存商品は保存前に候補を警告するが、自動統合しない。
- カタログ作業は未着手/作業中/登録済み、再確認日で絞り込める。登録済みにはASINが必要。期限判定は日本時間。
- 写真は明示的に選んだ既存ヤフオク紐付けの写真を再利用する。手元商品の新規撮影・アップロードはまだ未実装。

「以前のコンテナメモ」は過去の基準リスト。モニター31台、本15箱、ヘルメット色別要確認を現在の実数として取り込まない。商品名を入力欄へ移す操作も数量を埋めず、保存操作ではない。

## 保存・通信失敗

同じNeon/同じログインの `app_storage.documents` に `physical-stock` を追加し、従来の紐付け/下書き文書を作り直さない。第一段階は版付きJSONB内に商品/残高/移動/変更履歴/操作受付を分離して保持する。行ロック・トランザクション・版番号を既存保存基盤から再利用する。

2026-10-26のUI改善はDB移行不要。旧createの場所1つ/数量の形式も受け付け、新createの `initialCounts` は両場所の数値またはnullを検証する。`count_locations` は指定した場所の3区分を一括で更新する。前後履歴・冪等ID・版競合・ロールバックは旧処理と同じで、新操作の導入により本番データの初期化/数量自動補完は行わない。

一覧は商品/コンテナ/自宅・会社/販売先の状況/操作の5列。取り置き0・使用不可0・移動中0は主表示から省き、管理ID/SKU/FBA参照/確認日時は「詳細」へまとめる。移動中に実数があるときだけ商品に表示する。「移動中」は出発済み未到着分で、場所の実数とは別。Lucideアイコンはビルド時に必要分だけ同梱し、CDN/外部アイコン取得は使わない。

- 操作UUID、内容ダイジェスト、本人ID、日時、理由、変更前後、移動・受領根拠を保存する。
- 同じ操作の再試行は同じUUIDで照合し、二重増減しない。古い版での棚卸し等は拒否し、最新状態から確認し直す。
- 応答が失われた操作は本人ID別のブラウザsessionStorageへ保留する。再読込後にサーバーの受付記録を照合するまで別操作を止める。保存済みなら数量を再変更しない。
- DB障害時に空台帳やローカル保存へ切り替えない。オフライン自動同期は未実装。確認できないときは同じ操作の結果確認・再試行を使い、別タブで同じ数量を手入力し直さない。
- 初期上限は1,000商品/10,000操作/文書8MiB。超過時はエラーで止め、履歴を消して継続しない。規模が増える前に残高/履歴の正規化・ページ分割と配備側の応答容量を見直す。
- CSVは本人認証後の出力のみ。数量未確認は空欄、式として扱われる先頭文字を無害化する。CSV取込・売上による自動減算・Crossmaへの更新は実装していない。

## 移行と検証

`003-physical-stock.sql` は空の専用文書を追加するだけ。`scripts/prepare-physical-stock.mjs` は専用DBの直接接続とホスト明示を必須にし、既存文書のハッシュ不変を確認、再実行で上書きしない。実行ロールの権限はSELECT/UPDATEのまま。管理用資格情報を配備しない。

`tests/physical-stock.test.mjs`、`tests/physical-stock-database.mjs`、`tests/physical-stock-browser-flow.mjs` で区分保存、移動保存則、競合/ロールバック、失われた保存応答、再読込、認証、PC/390px画面、CSVの実配備ルートを確認する。DB/画面の数量変更試験は実開発Neon内の自分の一時文書だけで実施する。
