# 手元在庫の操作と保存仕様

更新: 2026-10-26。進捗の正本は [status.md](status.md)。本書はフェーズ2Aの手入力台帳の仕様・操作手順。

## 入口と最初の1商品

https://amazon-yahoo-inventory.vercel.app/?view=stock を開き、いつもの本人アカウントでログインする。上部の「手元在庫」からも移動できる。PCの起動やPowerShellは不要。

1. 「商品を登録」を押す。既存の紐付けがあれば選ぶ。ない商品やASIN未作成の商品も登録できる。
2. 商品名、新品/中古を入力する。単位選択はなく、新規登録は「個」に固定。同じ型番でも状態やセットが違えば別商品にする。状態・付属品・セット内容は任意で、空欄でも進められる。
3. 「場所ごとの数量」にコンテナと自宅・会社の使用可能数をそれぞれ入力する。同じ現物を2か所に足さない。未確認なら空欄にする。0は在庫なし、空欄は未確認。片方だけでも両方同時でも登録できる。
4. 必要ならメモを入力する。「Amazon・ヤフオク／カタログ設定」内の追加項目は任意。既存の紐付け選択もこの詳細内にある。
5. 「変更内容を確認」で変更前後を見て、「この内容で保存」を押す。確認だけ、または閉じただけでは保存しない。
6. 一覧の管理ID・場所・数量を見て、「更新」やページ再読込でも残ることを確認する。

最初は本人が実際の1商品でこの流れを確認し、その後に残りを登録する。試験用の架空商品を本番へ自動登録していない。390px幅の検証は済んでいるが、PC停止中の実機スマホ回線の確認は本人と行う。

## 数量の操作

普段は商品行の「数量を編集」、または各場所の数量/未確認を押す。コンテナと自宅・会社の実数を入力し、変更前後を見て保存する。Dellのコンテナ3個が登録済みで、自宅に1個ある場合はコンテナ3のまま自宅1とする。これは操作説明であり、今回本人の代わりに1を登録してはいない。数量を空欄にして確認済みデータを消すことはできず、在庫なしには0を明示する。

「数量を編集」は使用可能数だけを対象にし、既存の取り置き/使用不可数を保持する。変更した場所だけを1操作として版番号付きで原子的に保存する。変更理由は任意入力で、空欄なら「場所ごとの実数を確認」を履歴へ残す。

増えた分・減った分を記録する場合は「入出庫・移動」を開く。まず「入庫」「販売・持ち出し」「場所を移す」の3モードを表示する。取り置き、使用不可、区分別棚卸し、到着/戻しは「その他の操作」内。毎回変更前後を確認して保存する。

| 操作 | 意味 |
| --- | --- |
| 追加 | 今の使用可能数に足す。6台に3台追加なら9台 |
| 減少 | 販売・持出しなどで使用可能数から減らす。Amazon/Crossmaの処理とは連動しない |
| 棚卸し | 使用可能・取り置き・使用不可それぞれの実数へ合わせる。実数3台なら3台へ修正 |
| 取り置き/解除 | 使用可能と取り置きの間を振り替える。現物総数は変わらない |
| 使用不可/復帰 | 使用可能と使用不可の間を振り替える。現物総数は変わらない |
| 移動・納品の出発 | 出発元の使用可能数を減らして移動中へ移す |
| 到着/出発元へ戻す | 未到着の範囲内で振り分ける。一部到着も可能 |

場所別の現物数は「使用可能+取り置き+使用不可」。使用可能から取り置きをもう一度引かない。未確認の場所は先に棚卸しする。使用不可品の廃棄や取り置き品の販売は、必要な区分へ戻してから減少させる初期構成で、外部への廃棄依頼等はしない。

移動中は出発元・到着先の両方に重複計上しない。到着先が未確認なら実数を棚卸ししてから到着を記録する。到着済み数量と移動中の数量は別である。

FBAへの出発には納品番号などの参照を必須にし、FBA到着には受領画面等の確認根拠を残す。この手入力はFBA観測値を増やさない。FBA数量はAmazonから確認した別の参考情報として表示し、手元在庫との総合計や、ヤフオクへ発送可能な数量として保証しない。古い情報・取得失敗・SKU/状態不明は数量不明。

## 商品情報・カタログ待ち

- 「情報・メモ」で商品名、メモ、ASIN/SKU、既存紐付け、FBA納品可否、カタログ作業状態、再確認日を更新できる。
- 管理IDは固定。後からASINが付いても商品IDや数量は変わらない。
- 単位・新品中古・状態/セット内容の変更は別商品登録を求める。数量の自動変換や同じASINの合算はしない。単純な誤字訂正も初期版ではロックされるため、本人確認後の改善候補。
- 新規登録の単位は「個」で固定するが、旧データの台/箱等を勝手に個へ変換しない。既存商品編集では元の単位を非表示項目として保持する。過去のコンテナ参考リストの台/箱も過去の記録なのでそのまま残す。
- 同じASINまたは商品名の既存商品は保存前に候補を警告するが、自動統合しない。
- カタログ作業は未着手/作業中/登録済み、再確認日で絞り込める。登録済みにはASINが必要。期限判定は日本時間。
- 写真は明示的に選んだ既存ヤフオク紐付けの写真を再利用する。手元商品の新規撮影・アップロードはまだ未実装。

「以前のコンテナメモ」は過去の基準リスト。モニター31台、本15箱、ヘルメット色別要確認を現在の実数として取り込まない。商品名を入力欄へ移す操作も数量を埋めず、保存操作ではない。

## 保存・通信失敗

同じNeon/同じログインの `app_storage.documents` に `physical-stock` を追加し、従来の紐付け/下書き文書を作り直さない。第一段階は版付きJSONB内に商品/残高/移動/変更履歴/操作受付を分離して保持する。行ロック・トランザクション・版番号を既存保存基盤から再利用する。

2026-10-26のUI改善はDB移行不要。旧createの場所1つ/数量の形式も受け付け、新createの `initialCounts` は両場所の数値またはnullを検証する。`count_locations` は指定した場所の3区分を一括で更新する。前後履歴・冪等ID・版競合・ロールバックは旧処理と同じで、新操作の導入により本番データの初期化/数量自動補完は行わない。

一覧は商品/コンテナ/自宅・会社/操作の4列。取り置き0・使用不可0・移動中0・未紐付けFBAは主表示から省き、管理ID/SKU/FBA参照/確認日時は商品の「詳細」へまとめる。移動中に実数があるときだけ商品に表示する。「移動中」は出発済み未到着分で、場所の実数とは別。Lucideアイコンはビルド時に必要分だけ同梱し、CDN/外部アイコン取得は使わない。

- 操作UUID、内容ダイジェスト、本人ID、日時、理由、変更前後、移動・受領根拠を保存する。
- 同じ操作の再試行は同じUUIDで照合し、二重増減しない。古い版での棚卸し等は拒否し、最新状態から確認し直す。
- 応答が失われた操作は本人ID別のブラウザsessionStorageへ保留する。再読込後にサーバーの受付記録を照合するまで別操作を止める。保存済みなら数量を再変更しない。
- DB障害時に空台帳やローカル保存へ切り替えない。オフライン自動同期は未実装。確認できないときは同じ操作の結果確認・再試行を使い、別タブで同じ数量を手入力し直さない。
- 初期上限は1,000商品/10,000操作/文書8MiB。超過時はエラーで止め、履歴を消して継続しない。規模が増える前に残高/履歴の正規化・ページ分割と配備側の応答容量を見直す。
- CSVは本人認証後の出力のみ。数量未確認は空欄、式として扱われる先頭文字を無害化する。CSV取込・売上による自動減算・Crossmaへの更新は実装していない。
