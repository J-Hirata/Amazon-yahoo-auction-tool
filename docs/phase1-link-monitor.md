## 将来案：コンテナ・自社倉庫・自社発送（フェーズ2または3）

- コンテナや自社倉庫にある実物在庫も商品へ紐付け、保管場所ごとの残数を把握したい。

- 同じ倉庫在庫を使い、Amazonの自社発送とヤフオクの自社発送を併売する流れを検討したい。
- 保管場所（FBA・コンテナ・倉庫）、販売先（Amazon・ヤフオク）、発送方法（FBAマルチチャネル・自社発送）、FBA納品可否を別々に整理する。同じ実物在庫を販売先ごとに二重計上しないことが設計上の確認点。
- 将来設計時に、既存在庫台帳との連携、数量の更新方法、注文分の引当、FBAへ移動中の扱い、状態・付属品違いの区別を調べる。現時点で在庫移動・出荷・追加納品・出品変更を実行しない。

## 開き方

既存管理画面 `http://localhost:41731/` 上部の「商品紐付け・通知」を押す。同じツール内の `http://localhost:41731/link-monitor.html` が開く。別のツールや別ポートを起動する必要はない。

`start-link-preview.cmd` または `npm run preview:links` は互換の起動入口として残し、同じ41731の追加ページを開く。「下書きQへ戻る」で元の管理画面へ戻れる。

## まず練習

初期表示は「商品の紐付け」。「通知の動作テスト」へ切り替えると、架空の商品で通知見本を確認できる。練習は保存せず、模擬送信は外部に接続しない。

## 登録商品

1. 「Amazonの商品URL または ASIN」に、ASINまたはAmazon.co.jpの商品URLを入れる。
2. 「ヤフオクの出品URL」に商品ページのURLを入れる。
3. 同じ商品・状態・付属品であることを確認し、「この2つを紐付ける」を押す。
4. 直下の一覧で、Amazonページとヤフオクページの対応を確認する。詳細は行の「補足」、解除は確認後に行う。

SKU入力やCSV取込は不要。以前読み取った未紐付け出品が1件だけあり、管理番号のASINも1つなら、2欄へ初期表示するだけで自動保存はしない。同じ出品を別ASINへ黙って上書きしない。Amazonの短縮URL・検索ページは対象外。

ページの対応登録とFBA在庫確認は別。紐付け一覧の「FBA在庫を確認する」は登録したASINだけを対象に手動取得する。Amazonの全在庫は取得しない。ASINで自社の出品を検索し、得られたSKUだけをFBA在庫APIへ渡す。SKUの手入力は不要。初回のAmazon出品者ID確認は必要で、未確認なら停止する。分からない場合の全件取得への切替は行わない。

結果は各ASINの下に「FBA在庫：○個」または「要確認・取得できず」などで表示する。数量が正でも、マルチチャネル出荷条件・未反映の引当を確認済みとは扱わない。取得失敗・欠損・古い情報・対象不明を0と判定せず、複数のSKUの数量を勝手に合算しない。Yahooの状態も読み取っていなければ不明。通知の補足へSKU・在庫内訳・時刻・根拠・メール全文をまとめ、実送信はしない。

CSV・SKUを使う既存の詳細操作は「詳細設定・データ取込」に残すが、通常操作では開く必要はない。

## 在庫入力

列：`sellerSku,asin,fnSku,title,condition,setContents,fulfillableQuantity,externalCommitments,mcfEligibility,managementNumber`。
Amazonレポートの `seller-sku`/`sku`、`fnsku`、`product-name`/`item-name`、`afn-fulfillable-quantity`、`afn-reserved-quantity`、`afn-unsellable-quantity` も対応。UTF-8を使用。

- `externalCommitments` はFBAに未反映の確定引当分のみ。FBA引当済み分を二重に引かない。不明は空欄。
- `mcfEligibility` は出荷条件確認済みなら `verified`、未確認は空欄か `unknown`。Amazonでの販売可否とは別。
- 時刻不明・情報が古い・数量欠損・不正値は「確認できず」。0と推測しない。
- 明示的な出荷可能数量0はゼロ判定。正の数量は出荷条件・未反映引当を確認した数量と、1出品に必要な数量を比較。
- プレビューの鮮度上限90分。実運用の期限は接続検証後に確認する。
- 同じSKUでもASIN・FNSKU・状態・セット内容や説明内管理番号が変わったら再照合する。

## 出品終了と再出品

構造化データでIDと状態を照合。終了予定日や経過日数だけでは終了判定しない。異なる確認時刻で2回連続して終了を確認する。途中の取得失敗・古い観測は確認をやり直す。理由や後継の有無を確認できない場合は不明と記す。

後継IDは読み取り済みの出品から選び、出品者・管理番号・SKU・状態・付属品を確認した根拠を入れて引き継ぐ。題名だけでは引き継がない。ID維持の再開は出品中の観測で復帰を記録する。

## 通知と安全範囲

確定状態と観測結果を別に保存。0継続時は重複を抑制し、復帰と再発は別イベント。取得失敗を挟んでも最後の確定状態を保持。実データのイベントも `preview` のみで、送信・定期稼働をONにするAPIはない。既存の出品データは変更しない。
