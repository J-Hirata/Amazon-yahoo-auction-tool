## 認証と公開範囲

ブラウザは `@neondatabase/auth` の標準メール/パスワード方式を使用する。パスワードをこのアプリのAPI・ログ・保存データへ送らず、管理されたNeon Authへ直接送る。ログイン成功/失敗後は入力欄を消す。独自の認証パスワード台帳は作らない。

業務APIは `jose` で署名・発行元・有効期限・発行時刻を検証し、`sub` がDB内の本人IDと一致した場合だけ許可する。メールアドレス・表示名・画面の申告・先着ユーザーを管理者の根拠にしない。署名検証が通る前に業務レコードや本人設定を読まない。未登録の本人IDでは業務APIを403で拒否する。設定自体の不備は503で閉じる。

初回だけ256ビットのランダム招待を使う。URLのfragmentから読み取って直ちにアドレス欄から消し、DBにはSHA256だけ保存する。招待の24時間有効期限と署名検証済みのユーザーIDを行ロック内で照合して本人を一度だけ設定する。別IDへの変更は禁止、同一IDの再試行だけ冪等。招待はGit対象外の本人専用ACLファイルに保管し、チャット/アクセスログ/配備物に出さない。パスワードをエージェントが作成・入力する方式ではない。本人登録の完了と実ログインは2026-10-26に確認済み。

JWTは短期トークン。ブラウザのログアウトで画面と認証セッションを終えるが、すでに発行されたJWTの即時失効を保証した仕様ではない。公開時には有効期限、アカウント停止/本人ID差替えの手順も確認する。

## 起動設定

秘密の値をチャットに貼らない。専用DBの接続情報は保存層の安全な設定から引き継ぎ、以下をサーバー専用の秘密設定で指定する。

| 変数 | 内容 |
| --- | --- |
| `ASIN_STORAGE_BACKEND` | `postgres` 固定。クラウド版はJSONへ接続しない |
| `ASIN_DATABASE_URL` / `ASIN_DATABASE_EXPECTED_HOST` | 専用DBと確認した接続先。ブラウザへ返さない |
| `ASIN_PUBLIC_ORIGIN` | 公開先の正確なHTTPS Origin。ローカル試行だけHTTPループバック可。Vercelのpreviewのみ、サーバー環境の `VERCEL_URL` からその配備のOriginを採用できる。リクエストのHost/転送ヘッダーやproductionの推測値は使わない |
| `ASIN_NEON_AUTH_URL` | 同じ専用NeonブランチのManaged Auth URL。公開される設定値で、DB接続文字列ではない |
| `ASIN_OWNER_USER_ID` | 固定本人ID方式を使う場合のみ。現在のDB方式と併用は禁止 |
| `ASIN_OWNER_FROM_DATABASE` | 本番は `1`。専用 `app_security.owner_access` の本人IDを署名検証後に照合する |
| `ASIN_CLOUD_FULL_WORKSPACE` | 本番は `1`。既存の下書きQと従来の操作欄を含む画面を提供 |
| `ASIN_CLOUD_READ_ONLY` | 省略/`1`で閲覧のみ。`0`の明示指定がある場合だけ許可した保存操作を有効化 |
| `ASIN_PUBLIC_DEMO` | `1`の場合だけ架空データの公開確認APIを許可。業務APIの認証を解除しない。現在の業務配備では指定していない |
| `ASIN_AMAZON_CLIENT_ID` / `ASIN_AMAZON_CLIENT_SECRET` / `ASIN_AMAZON_REFRESH_TOKEN` | 本人承認で既存値を専用productionのSensitive設定へ登録。元の設定は保持。ブラウザへ返さず、ログ/配備物へ埋め込まない |
| `ASIN_AMAZON_MARKETPLACE_ID` / `ASIN_AMAZON_SELLER_ID` | 既存の自社アカウント識別と整合する日本市場/販売者。クライアントの任意指定を受け付けない |
| `ASIN_GMAIL_USER` / `ASIN_GMAIL_APP_PASSWORD` | 同じ本人指定のGmailと送信用アプリパスワード。production Sensitive設定。送信元/先を固定し、Windows資格情報ファイルは配備しない |

接続用の新ルートは `POST /api/link-monitor/fba-check`、`GET /api/link-monitor/fba-status`、`POST /api/link-monitor/mail/verify`、`POST /api/link-monitor/mail/test-registration`。書込操作は本人JWT/Origin/JSON本文/`If-Match`を検証し、旧版は外部呼出前に拒否する。メールテストは追加で `confirmed:true` が必要。任意ASIN/宛先/URL/認証情報をリクエストへ渡す仕様ではない。

FBA取得は最長40秒の取得予算、関数60秒の中で完了させる。DBにジョブID/期限を先に確保して並列取得を抑止し、対象/アカウントの変更や古いジョブによる上書きを拒否する。関数終了後のメモリ内タスク/タイマーに依存しない。中断は期限後に要確認として表示する。

GmailテストはDBに試行1回/再試行禁止を保存してからSMTPへ進む。受付後のDB応答喪失も無条件再送せず、不明扱いで確認する。実際に送ったのは00:58:07の承認済み1通だけで、本人が到着を確認済み。毎時注文通知の完成・有効化とは別である。

```powershell
npm run build:cloud
# 上記の安全な環境設定と本人ID確認後だけ実行する
npm run start:cloud
```
