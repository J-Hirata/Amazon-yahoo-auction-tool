## 修正

1. 通知カテゴリ変更で取り消された送信待ちの同じキーが再登録を妨げ、販売イベントがqueuedのまま取り残される。取消記録と過去文面を履歴保存して、未送信の同じ記録を再受付する。受信結果不明/受付済みは自動再送しない。明確な送信失敗は累計最大3回。
2. 通知生成とメール保存の間の設定変更に対応。メール側が実際に受付けたIDだけをqueuedとして記録。受け付けなかったIDは次回に残す。
3. 送信/再送の直前に保存済みの最新在庫・出品・設定を再評価。回復/解除/別SKUは取消、取得失敗/古い観測は保留。Yahoo終了の案内文も最新の同SKU残数から作り直し、在庫0なのに古い「在庫8個・再出品」を送らない。過去本文は履歴に残す。
4. 回復後の再低下は別の通知IDと結び、古い待機通知と新しい警告を重ねて送らない。
5. 在庫/出品監視の例外や処理時間切れを、販売取得の失敗とは別に自動確認の未完了通知として記録する。

閾値、実在庫、出品、Cron頻度は変更しない。確認済みの終了だけを対象とし、取得不能を終了や0にしない。既存の送信条件・履歴の意味を保つ。本番の試験メール送信や手動Cronは行わない。
