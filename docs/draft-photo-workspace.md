# 下書きツール内の写真仕分けナビ共有写真

2026年11月12日。共有写真をヤフオク出品下書きツールの中へまとめる本人の指示に対応する。

## 操作

1. 写真ナビで商品を選び「コックピットへ共有」を押す。「下書きツールで共有写真を開く」から受取先へ進む。
2. 販売コックピットの「ヤフオク出品下書きツール」を開く。中の「出品下書き」「写真仕分けナビ共有写真」で切り替える。上段の独立した共有写真カードはなくす。
3. 共有写真の「この写真で下書きを準備」で商品名、商品説明、開始価格、作業メモを入力する。既存下書きがある商品はそれを開く。
4. 代表写真がある場合は初期選択する。未設定なら使う写真を選ぶ。使う写真だけチェックし、「先頭にする」で代表と並び順を決める。拡大画像は同じ画面で前後へ切り替えられる。タグだけ・暗い・重複した写真は外す。
5. 保存すると「出品下書き」の「写真からの下書き」へ戻る。既存の「ASINからの下書き」も同じページに残す。
6. 「写真・文面をまとめて取得」で保存済みの写真と文面をPCへ取得する。「ヤフオクの入力画面へ」で進み、写真・文面・価格などを入力して確認する。

ツール内の下書き保存と、Yahoo側での入力・下書き保存・出品確定を分ける。写真からの下書きの画像をChrome拡張へ自動転送する機能は今回追加しない。既存のASIN下書き用拡張1.0.4は従来のまま使える。

入力が途中でもツール内へ保存できる。商品説明と開始価格が揃った下書きは「下書き内容入力済み」、未入力なら入力案内を表示する。Yahooでの保存・出品完了という記録は自動で作らない。

## 写真・文面の取得内容

- 01.jpg、02.jpg…：選んだ順番の保存写真（最大10枚）。先頭が代表写真。
- 出品下書き.txt：商品名・開始価格・商品説明。UTF-8 BOM付き。
- 作業メモ.txt：作業メモを別ファイルにする。出品文面には混ぜない。
- 写真対応.json：商品・写真セットID、写真ID、元ファイル名、写真のハッシュと、選択写真に対応する型番/JAN。JANは文字列で先頭0を残す。

写真の取得に失敗した場合はZIPを作らず理由を表示する。ZIP取得によって掲載済みや出品済みに変更しない。

## 保存・個体対応

- 写真本体は写真ナビの既存の非公開保管を参照する。新たなクラウド写真コピーを作らない。
- app_storage.documents の既存 photo-library に listingDrafts / listingDraftOperations を必要時に追加する。写真セット・在庫関連付け・既存の操作履歴は保持する。スキーマ移行や権限拡張は不要。
- 下書きIDは写真側の作業環境ID＋商品ID＋出品先から決める。ASINがなくても使え、同じASINの別個体は統合しない。現在の出品先は yahoo のみ。Amazon・メルカリを追加する際もこの対応と画面内の区分を拡張する。
- 既存の draft-items（ASIN下書き）や在庫文書は書き換えない。売価の自動計算・在庫数量更新・外部登録も行わない。
- 元の写真セットは固定する。写真ナビから新しい版を受け取っても、下書きの写真を勝手に替えない。切替ボタンを押し、使う写真を選び直して保存する。
- 同じ保存操作の再送は重複させない。共有ライブラリーの版と、商品ごとの下書きの版を確認する。競合時は入力を残し、既存下書きを上書きしない。
- アーカイブと復元は下書きの区分を変える。写真・文面・写真ナビの元データは保持する。

## 画面と互換リンク

- 下書きの入口： https://amazon-yahoo-inventory.vercel.app/?view=drafts
- 共有写真： https://amazon-yahoo-inventory.vercel.app/?view=drafts&section=photos
- 旧 ?view=photos は新しい共有写真へ表示を引き継ぐ。既存の在庫写真リンクも新しい入口へ変更する。
- 写真ナビの共通リンクも下書きツールへ直接進む。写真ナビの仕分け・型番/JAN抽出・TXT/Excel出力・プライスター等への入口は維持する。

本人認証・Origin・閲覧専用・JSON形式・If-Match の制限は新APIにも適用する。
GET/POST /api/photo-listing-drafts と、GET /api/photo-listing-drafts/{id}/export/{version} を使用する。画像取得は既存の非公開共有写真APIを使い、サイズとハッシュの照合を維持する。

## 検証

- コックピット483テスト（写真下書きの新規9件を含む）とクラウド画面ビルド、写真ナビ72テストと型チェック。
- 専用QA用DBと合成JPEGで、メニュー切替→タグを外した写真選択→先頭変更→ASINなしの保存→再読込→ZIP→編集→アーカイブ/復元を実行。
- 独立したZIP読取で写真のバイト・順序・タグ除外・日本語ファイル名・内部メモ分離・JAN先頭0を確認する。
- 既存のQA用ASIN下書き・在庫・元写真セット・既存文書は不変。本番の実商品を試験目的で作成・出品しない。
- 証跡は output/draft-photo-workspace-20261112/。公開前後の本番文書照合と公開資産の確認は同フォルダーへ保存する。
