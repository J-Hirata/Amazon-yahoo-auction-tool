# 商品別の案内・3日ごとの再案内

## 現在地

2026-11-12。本人指定の3日間隔、通知回数、個別解除、設定への直接移動を実装した。全496テストと独立QAのDB・ブラウザー操作が合格。公開・本番ポリシー反映の結果は末尾へ記録する。

## 本人が選択した動作

- 初回を通知1回目、3日後を通知2回目、さらに3日後を通知3回目として、未対応なら3日ごとに再案内する。日付は日本時間。既存の日次確認（午前9時台）で判定し、Cronの頻度は変更しない。
- メールは「新しい案内」を上、「再案内（3日ごと）」を下へ固定し、それぞれ再出品・残数警告と補充・販売見直し等に分類する。共通の確認時刻は1か所、商品ごとの内容は要点と名前付きリンクにする。HTMLとプレーンテキストの両方を送る。
- メールの「確認・再案内の解除」から、その案内の管理画面を直接開く。「この件の再案内を止める」にチェックすると、その件の再案内を解除する。チェックを外すと再開できる。再案内一覧は全商品一覧の「通知・再案内」からも開ける。
- 残数設定・見直し日・方針への変更ボタンを表示する。残数の設定を開いた際は入力欄へ直接移動する。
- 解除は現在の案内にだけ効く。しきい値・対象SKU・見直し日・出品IDの変更、回復後の再不足、正の在庫から0への悪化は新しい案内として扱う。同じ基準内の小さな減少では解除を勝手に戻さない。

## 保存と配信の境界

既存のproduct-watch文書へ任意のnoticePolicy / noticeControls / noticeReceiptsを追加する。旧データは従来どおり読める。ポリシー未反映では定期再案内を開始しない。在庫・金額・写真・下書き・計画の入力値や既存メールの受付記録を書き換えない。

案内の元IDを保ち、SMTPが受け付けた送信記録だけを回数に数える。待機・拒否・結果不明は回数を増やさない。SMTP結果不明は従来どおり自動再送しない。明確な拒否の再試行は最大3回。キューは元IDと通知回数で重複を防ぐ。送信直前にも最新の保存済み在庫・条件を照合し、解消・解除・不明の案内を送信しない。

メールのリンクを開くだけでは解除しない。本人の認証済み画面でのチェック保存が必要。保存は世代確認と操作IDで競合・二重操作を防ぐ。解除済みは標準一覧から除き「解除済みも表示」で確認できる。

既存の案内はポリシー開始日から3日待つ。旧残数警告に直前数量がない場合は、開始時点の既知数量を補助情報として保持し、以後の0への悪化を判別する。これは在庫数量の手入力補正ではない。
