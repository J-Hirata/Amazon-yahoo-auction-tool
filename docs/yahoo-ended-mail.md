# ヤフオク終了通知を在庫と次の作業へ絞る

2026-11-10。本人が添付したロゴスの落札終了メールと、FBA8個・ヤフオク終了0個の画面を根拠とする。ローカル実装・隔離検証まで。本番未反映・実メール未送信。

## 本文と判定

- 商品名/ASIN、確認日時、出品ID/終了、次の作業を先頭にする。既定では同一SKUのFBA取得在庫を使い、十分な在庫があれば再出品を明示する。設定値や数量は変更しない。
- 落札ありの終了でも残在庫があれば再出品を案内する。落札有無は観測結果で確認できたものだけを表示。不明時は「出品終了」だけで、売れ残り扱いしない。
- FBAは26時間以内・同一SKUの取得成功値だけで判断。予約数・手入力・推定数量を現在のAPI在庫へ置き換えない。手入力は本文で別表示するが再取得を案内する。数量を今回のヤフオク落札分で自動減算しない。
- 0個は補充/別在庫へ切替、未取得は再取得、商品/SKU不一致は紐付け修正、関連出品ありは重複再出品不要、関連出品未確認はその状態の再取得を指示。セット数不足も再出品を勧めない。
- 本人が選んだ別の残数参照元は優先する。台帳は現物の自動同期ではないため実数照合、自社発送出品数量は現物残数の照合を案内する。FBA8個を理由に選択済みの別在庫0個を無視しない。
- 在庫/計画を未登録の場合は「記載なし」。台帳あり数量なしは「数量未入力」、実数0は「0個」。FBA・台帳には根拠日時を残す。
- 全商品一覧、Amazon商品、コンテナ・自社在庫、販売の監視・見直しへ直接リンク。関連計画が1件なら既存の#idで開く。一般的な前置き・重複リンク・末尾の操作しなかった説明を省く。終了以外の従来通知だけのメールは変更しない。

## 実装境界

product-alert-mail.jsは保存済みの観測から本文を作る純粋関数。product-alerts.jsの終了通知から使い、既存の通知ID/条件キー/重複抑止は維持。cloud-sales-automation.jsの同じ保存・送信経路へ本文を渡す。書式変更だけで既送信の終了通知を再作成しない。未送信の古い通知本文も書き換えない。

公開ページ解析では終了と入札0から落札なしを確認できるが、入札ありだけでは落札成功と断定しない。今回の添付には落札者ありのメールがあるので非送信見本では落札ありを使うが、これを本番DBの観測へ代入しない。Gmailの受信解析・落札結果の自動取込みは今回未接続。再出品、出品URL変更、数量/価格変更、MCF発送は自動実行しない。
