# 在庫登録と通知メモ・販売監視の同時設定

## 現在地

2026-11-18。登録を妨げていた任意の納品欄を修正し、通知時のメモと販売監視の期間・目的を商品登録/共通編集の同じ画面で設定できるようにした。全571テストと隔離ブラウザーの新規登録・保存・再表示・監視日数の編集が合格。本番公開の照合を進めている。

次の一手：公開URLの表示と保存データ不変を照合し、本人は入力中の画面を保存してから再読込して新しい欄を利用する。

## 操作

- 通知残数の下に「通知時のメモ（任意）」を追加。例の「90個以下になったら追加納品」を自由に記載できる。既存の商品の確認メモを参照・更新し、残数警告などのメールと確認画面にも表示する。閾値やメモを代理入力しない。
- 「販売監視・見直しにも登録する」を選ぶと、直下に開始日・確認日数・目的メモを表示する。登録済みの監視も同じ窓で編集できる。既存の広告監視と日付指定の確認は対応する日付を表示し、複数計画は対象を選ぶ。変更した項目だけを保存し、既存の方針・個別アクション・関連商品・作成日は維持する。
- 開始日・メモは任意。開始日が空欄なら日数計測はまだ始めず、販売個数も推測しない。日数空欄は既存値を保持し、新規は従来の10日を使う。
- 「FBAへの納品予定（任意）」は使う場合だけ開く。予定数を入れず日付・納品番号/メモだけ入力しても、数量未定の下書きとして商品と一緒に保存・再表示できる。数量が決まったら同じ欄に入力して実際の納品予定へ切り替わる。未入力を0個や到着済みにしない。どちらも現物在庫・Amazon数量へ自動加算/減算しない。

## 原因と保存方法

従来は納品の予定日またはメモだけで「納品予定の個数を入力してください」と例外を出し、商品登録全体を止めていた。また同時登録の販売監視は空の日付で計画を作るだけで、設定を別ページで探す必要があった。

通知メモは既存product-watchのrule.noteを明示参照の対象だけ更新し、履歴を残す。販売監視は既存sales-planningの同じ計画へ差分保存する。数量未定の納品下書きはlink-monitor.fbaIncomingDraftsに保存し、実際のfbaIncomingとは区別する。DBテーブルやCron・通知頻度の追加/変更は不要。確認プレビュー・世代検査・一括トランザクション・操作ID再試行は維持する。

## 検証と影響

追加6件を含む全571テストが合格。新規の自宅100個/コンテナ未確認・通知メモ/閾値・監視期間・数量未定の納品下書きを一度に保存し、再試行の重複なしを確認。下書きから予定数50個への切替でも現物数量は不変。メモだけで閾値を有効にしないこと、別商品の計画IDと不正日付の全体ロールバック、計画の方針/アクション保持、メール表示へのメモ反映を確認した。

隔離ブラウザーでは架空ASIN B000QA1801を使い、新規登録→同じ窓で確認→保存→開き直し→監視10日から14日への変更を確認。自宅100個・通知90個・改行入りメモ・開始日・目的メモ・数量未定の予定日/メモが再表示された。本番商品を試験登録していない。本人の入力中タブは読み取りで確認し、再読込や入力変更を行っていない。

証跡はoutput/stock-monitor-inline-20261118/。業務スナップショットはGit対象外。実メール・手動Cron・外部出品/価格変更は行わない。既存の受信メール改善と写真下書きは保持する。

## 戻し方

問題があれば公開前に記録した直前の配備へコードのみ戻す。新しい任意のfbaIncomingDraftsは旧コードでは参照されないが削除しない。商品・数量・通知履歴・注文履歴を過去の控えで戻さない。既存の未コミット文書はバックアップと保全確認を行って正本へ同期する。
