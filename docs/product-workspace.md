## 運用と数量

通常の発送はFBAを先に消化し、コンテナ・会社はFBAへの補充元とする。緊急時の直送は本人判断。FBA不可の自己発送商品は別用途のまま保持する。FBA販売可能数に補充元を足さず、ヤフオク必要数の超過警告を消さない。

紐付け・実在庫・販売の監視と見直し・全商品一覧で同じ商品を参照する。4画面ともFBA、ヤフオク、コンテナ、会社・自宅を別表示する。未登録・未関連・未確認・0は別の状態。取り置き・使用不可・納品中を補充可能数に足さない。

例: FBA8、ヤフオク2出品5+9、コンテナ15、会社1なら、FBA比で6個超過を残し、補充元も見えるようにする。現物15+1は1レコードで管理し、出品ごとに複製しない。Amazon保管容量の測定やMCF出荷保証ではない。

## カードからの操作

登録先は商品名に近い上部の色付きタグで示す。青「商品紐付け」、緑「コンテナ・自社在庫」、黄「販売見直し」。実際の参照があるものだけ1～3個表示し、同ASINの候補・未登録を登録済み扱いしない。タグ自体から該当ページへ移動でき、販売見直しは別タブ。完了計画も「販売見直し（完了）」で区別する。販売中/出品終了や数量とは別の情報。

下部は未登録分の次の操作を1つと「…」に絞る。「…」内に従来の関連ページ、未登録先への追加、補充条件、補足を保持する。用途や「在庫あり」「見直し登録済み」を下部へ重複常設しない。補充が必要な場合の警告は引き続き表面へ表示する。リストとタイル、紐付け/実在庫/販売見直し/全商品で同じ参照から表示する。

| 表示 | 動作 |
| --- | --- |
| 紐付け / 紐付け2件 | 同じ商品の紐付け画面へ移動し、対象カードを強調 |
| 実在庫 | 関連付け済みのコンテナ・自社商品へ移動 |
| 実在庫をつなぐ / 出品をつなぐ | 既存の現物と出品を確認後に関連付ける。URLの再登録は不要 |
| 実在庫候補を確認 | 同ASIN候補で絞り込む。複数候補から勝手に1件を選ばない |
| 実在庫を登録 | 元の商品情報を引き継いで入力を開く。数量は空欄から本人が入力 |
| 販売見直しへ / 販売見直し | 別タブで新規計画の入力、または既存の確認中計画を開く。元の作業タブを残す |
| 全商品 | その商品の共通行へ移動し強調 |
| 補充条件 | 全商品一覧の対象商品の監視・補充設定を開く |

移動だけでは保存しない。「販売見直しへ」は元の商品を移動・削除する操作ではない。同じ商品の確認中計画があれば別の同SKU出品からでもその計画を開き、重複作成しない。期間/日付/メモは元の計画のまま。

商品の上部タグ/カード/詳細欄から販売見直しへ進むリンクは、新規/既存ともtarget=_blankとnoopener/noreferrerを使う。元の実在庫・紐付け画面は再読込しないため、検索・並び順・スクロールを維持する。メニュー全体を別タブにする変更ではない。見直し側の未保存入力を閉じても元の商品や数量へ書き込まない。

## 同じ商品とみなす範囲

- ASINだけでは統合しない。実在庫側の明示出品参照を起点にASIN・SKU・新品中古/部品扱いを照合し、異なるSKU・状態は別行で保持する。
- SKU未選択は、自社アカウント/売主・対象ASIN・取得完了・鮮度を満たすFBA候補が1件の場合だけ解決する。失敗/古い情報/複数SKUは不明。旧90分参照が古いというだけで最新の候補を拒否しない。
- 明示関連された現物は、同ASIN・同じ確認済みSKUを使う別の検証済み出品からも共通参照できる。必要なヤフオク数は出品IDの重複を除いて合計する。
- 同ASINの未関連実在庫は候補であり、確定数量として流用しない。関連付け保存時、空欄のSKUに一意の確認済みSKUを提案し、確認画面に変更前後を表示する。入力済みの別SKUは勝手に置換しない。
- 既存プレビュー/確定処理と保存世代・操作IDを使う。取消/競合/応答消失で現物を増減させず、保存後に共通参照も再取得する。DB移行・既存商品の再登録は不要で、本人の登録作業と並行できる。
- 既存の手入力計画はASINだけで付け替えない。その参照先補完は後段。URLフラグメントは登録IDだけを使い、秘密値を載せない。

## 基準数の半分になったときの補充

1. 商品の「補充条件」を開く。
2. 補充通知を有効にし、目安を「基準数の50%以下」にする。
3. 基準数を本人が入力、または確認済みの正のFBA数だけ「現在のFBA数量を使う」で指定する。0/不明から開始時数量を推測しない。
4. 保存する。最低7日販売数/残り日数も従来どおり指定できる。

基準20ならFBA10以下かつ使用可能な補充元在庫ありで候補。FBA不可、未取得/古いFBA、基準未設定では割合判定しない。割合モードでは旧初期値10個の条件を重ねず、固定数量モードも維持する。

同じASIN・SKU・設定基準で、以後の観測でより多いFBA数を確認したら観測上の最大数を補充基準にする。減少だけで基準を下げない。別SKU/設定し直した基準に以前の最大数を流用しない。観察間に増減して検知できなかった補充は推測しない。

既存の日次確認・stockAlertsの通知経路を使う。継続中は再送せず、解消後の再発は別通知。取得失敗を解消/ゼロにしない。「状態を再取得」は通知なし。保存だけでメール・納品・数量変更は行わず、既存の通知オン/オフや計画期間を無断変更しない。

## 2026-11-10 3ページの直接編集と関連登録

商品紐付け・コンテナ自社在庫・販売監視のカードから、小さな「商品情報・販路編集」で直接入力窓を開く。紐付けカードは一覧内の縦長詳細展開を使わず、販売監視も閲覧専用詳細を挟まない。「方針・日付」は従来の専用編集を保持する。

- 各ページの編集窓に、コンテナ・自社在庫／Amazon自社発送／ヤフオク／販売監視の登録先を表示する。登録済み在庫・監視はチェック済みで再作成しない。新規登録先は明示チェックを保存するまで追加されない。
- 紐付け・監視からも場所別数量、FBA基準、残数アラーム、納品予定を同じ窓で編集し、変更前確認も同じ窓内で行う。FBA納品予定の独立したタイルボタンは外す。Amazon・ヤフオクへの直接リンクは維持する。
- 同ASINだけで在庫を勝手に統合しない。既存の適合候補がある場合は選択して関連付ける。SKU・新品中古・セット内容が不整合なら全体を保存しない。登録済み在庫を選択しただけでは、その名前・メモ・用途・単位・カタログ作業・数量を置き換えない。
- 監視の元参照とIDは保持し、追加した実在庫は任意のworkspaceStockIdで明示参照する。既存の方針・開始日・確認期間・日付・判断メモ・履歴を初期化しない。旧画面の方針編集でも追加参照を保持する。
- ヤフオク出品済みのURLを引き継ぎ、登録済みの出品は同じIDを利用する。URLなしの準備は既存の下書きを再利用し、文面や保存済み状態を保持する。新しい不明URLの推測や外部出品は行わない。
- 紐付け・監視の共通編集は/api/product-links/previewとoperationsを利用する。在庫・紐付け・監視・アラーム・下書きを既存5文書の一括トランザクションで保存し、保存世代、操作ID、内容digestを検査する。競合・不正値は全体を戻し、応答不明の再試行で重複登録しない。プレビューは保存しない。新しいテーブルやDB移行は不要。
- 変更した項目だけを送る。未編集の場所別数量やFBA基準日時をリセットしない。商品名・画像等の手入力はローカル管理情報として保持し、取得済みのYahooページ情報を改変しない。実際の在庫・価格・出品・広告・メールは自動変更しない。

### タイルの重なり

登録タグを42pxへ押し込める制限と、販売監視の固定行高を解消した。タグ・SKU・現在の数量・納品予定・次の方針・操作が内容に応じた高さを持つ。小サイズでは4か所数量を2段にし、未登録等の文字を潰さない。長い商品名は2行、メモは要約表示し、全文は直接編集窓で読む。小・標準・大を保持し、表示切替でデータを書き換えない。
